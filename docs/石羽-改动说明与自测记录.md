## 一、本轮做了什么（精确摘要）

### 1. 品牌与顶栏

| 项 | 内容 |
|----|------|
| 产品名 | **走起不**（口语邀请，可延展广告：「饭点走起不？」） |
| 副标 | 想出门，就走起不 |
| Logo | SVG 吉祥物：黄圆角块 + 笑脸 + 迈步路线 + 小箭头 |
| 顶栏 |  sticky 布局；右侧「重置」；下方 **生活圈定位条**（可点击） |
| 底栏 | 图标 + 文字（发现 / 匹配 / 消息 / 我的）；选中项黄底高亮 |

### 2. 视觉体系（美团 / 小红书 / 多邻国混合）

- **主色**：美团黄 `#FFE033`、强调橙 `#FF6B35`、小红书红 `#FF2442`
- **卡片**：白底、轻阴影、18px 圆角；去掉早期「盐系灰」与 emoji 装饰
- **场景图标**：`scene-icon` 彩色底 + 单字（饭/咖/K…），替代 emoji
- **按钮**：多邻国式粗圆角主按钮 + 底部阴影
- **商户卡**：大图头图 + 红色人均 + 「团」角标

### 3. 地图页（发现）

- **平面示意地图**：四色分区块 + 白色十字路；去掉立体渐变与厚重 pin 阴影
- **Pin**：扁平白气泡；选中黄描边；热门橙/红标签
- **统计条**：横向滑动胶囊（生活圈 / 找搭子 / 活跃 / 圈内地点）
- **场景导航**：5 列金刚区 + 探索抽屉；按生活圈过滤 POI
- **商户 Sheet**：POI 详情、团购条、找搭子、需求 carousel

### 4. 生活圈全屏页（新增交互）

点击顶栏定位条进入 **「我的生活圈」**，包含：

- 实时感文案（「N 人正逛这个圈」+ 天气）
- 品牌 slogan 轮播
- 氛围条 + **现在 / 今晚 / 本周末** 时段切换
- 迷你平面地图（餐饮区脉冲动画）
- **圈子里正在发生**（动态流，可点进地图 POI）
- **大家在搜什么**（热搜气泡 → 填匹配条件）
- **常去角落**（横向店铺卡）
- **成局灵感**（三条预设 → 匹配页）
- **浏览范围** 2/3/5 km（已接入 `poisInCircle` 距离过滤）
- **切换生活圈**（4 个主题圈，见下表）
- 邀请卡片、打招呼列表、底部「用走起不匹配」

**四个生活圈**（`mockData.lifeCircles`）：

| id | 名称 | 筛选逻辑 |
|----|------|----------|
| near | 附近 · 生活圈 | distance ≤ 2.5km |
| eat | 美食热力圈 | 餐饮/咖啡/夜宵/酒吧 |
| play | 夜玩活力圈 | KTV/桌游/酒吧 |
| sport | 动起来圈 | 攀岩/骑行 |

### 5. 数据层补充（`mockData.js`）

- `brand`：名称、副标、slogans
- `lifeCircles`：圈配置 + `filter` 函数 + `trends` / `vibe`
- `circleWeather`：演示用天气文案
- 区域文案：`area` / `areaShort`（不再硬编码「三里屯」）

### 6. 工程小修复（自测中发现）

- `refreshMapSupply()`：切换生活圈 / 场景 / 半径后统一刷新地图 POI
- `browseRadiusKm` 真正参与 `poisInCircle` 距离过滤（此前仅 UI 展示）
- 生活圈内点店铺仅 `setPage("map")`，避免地图未初始化时重复渲染报错

## 二、页面真实度：哪些是「皮」，哪些能跑通

### 能跑通（Demo 级，有 mock 或规则层逻辑）

| 页面/模块 | 真实度 | 说明 |
|-----------|--------|------|
| 发现 · 地图 | ★★★☆ | 示意坐标非 GPS；POI/人数为 mock；筛选与生活圈联动可用 |
| 发现 · 场景 Tab | ★★★☆ | 过滤真实生效；数据仍为本地生成 |
| 匹配 | ★★★☆ | 规则层 `parseIntent` + `runMatching` 可用；配 Key 可走 `server.py` Agent |
| 匹配 · Top3 方案 | ★★★☆ | 可选中进聊天；分数为算法 mock |
| 消息 · 1v1 聊天 | ★★★☆ | 快捷回复、换店、改预算、模拟拒人有分支 |
| 消息 · 群聊列表 | ★★☆ | 成局后生成；消息本地追加，无推送 |
| 成局成功 | ★★☆ | 展示计划与团购；购买/日历/导航为 toast |
| 我的 | ★★☆ | 信誉分展示；字段来自 mockUser |
| 生活圈页 | ★★☆ | 交互完整；动态/热搜/人数多为 **合成演示**，非真实 feed |
| 诚意金 Sheet | ★★☆ | 局态机 UI；无真实支付 |

### 基本是皮（看起来能用，实际不可用）

| 模块 | 问题 |
|------|------|
| 生活圈 · 「N 人正逛」 | 公式推算，非实时在线 |
| 生活圈 · 动态流 | 用户+POI 组合生成，非真实帖子 |
| 打招呼 / 邀请卡片 / 分享 | 仅 `showToast`，无链接、无 IM |
| 地图 · 导航 | toast 示意，无跳转高德/美团 |
| 地图 · 用户定位 | 固定百分比点，非 GPS |
| 浏览范围 km | 按 POI 的 `distance_km` mock 字段过滤，非 geohash |
| 时段切换（现在/今晚/周末） | 只改文案，不影响匹配算法 |
| 高德 / 美团 POI API | `GET /api/meituan-poi` 返回 501 |
| 双边确认成局 | 对方确认多为 **定时器模拟** |
| 团购购买 | toast；无订单、核销、退款 |
| 稀疏模式 | 有开关，但默认数据仍偏「高密度商圈」 |

## 三、反思：为什么 Demo 容易「显得假」

1. **供给密度**：mock 同区大量 POI 与搭子，与生活圈「热闹」UI 互相加强，评审易误判为已上线产品。
2. **生活圈叙事 > 数据**：动态、热搜、氛围条设计先行，后端无 feed / 无 DAU，只能合成——**必须在文档和演示词里标明**。
3. **地图双轨**：UI 已是平面分区图，但文案仍混用「示意」；若接真地图需整页替换 canvas，不能 incremental patch。
4. **品牌多次迭代**：盐系 → 美团风 → 恰好 → **走起不**，部分旧截图/文档可能过期；以本文件与 `index.html` title 为准。
5. **半径与生活圈叠加**：先按圈 `filter` 再按 `browseRadiusKm` 截断，极端组合可能 **0 家店**——需产品定义空态（当前仅依赖 mock 密度避免）。

### 5.2 手工路径（建议演示前走一遍）

1. 发现 → 点定位条 → 生活圈页 → 切换「美食热力圈」→ 返回 → 地图 pin 数量变化  
2. 生活圈 → 点「常去角落」店铺 → 回发现并定位 Sheet  
3. 生活圈 → 热搜 / 成局灵感 → 匹配页输入框有内容  
4. 匹配 → 开始匹配 → 选方案 A → 聊天 → 模拟拒人 → 候补  
5. URL：`?script=reject` 自动拒人重算
